# todo1 — Task Manager

A full-stack task management application that lets users create, view, complete, delete, and
filter tasks, with an optional Chart.js statistics modal. The backend is a FastAPI + SQLAlchemy
REST API backed by SQLite; the frontend is a Vue 3 single-page application served by Vite, styled
with Bulma. Both components are generated from a graph-code blueprint (`blueprint/`) and verified
by an end-to-end integration suite.

## Running the full system

Start the backend first, then the frontend.

```bash
# Backend
cd apps/todo1/backend
pip install fastapi "uvicorn[standard]" sqlalchemy pydantic
uvicorn app.main:app --reload --port 8010
```

```bash
# Frontend (separate terminal)
cd apps/todo1/frontend
npm install
npm run dev
```

Open the frontend at `http://localhost:5180`. The dev server proxies `/tasks` and `/task` requests
to `http://localhost:8010` (see `vite.config.ts`); the api client itself calls
`http://localhost:8010` directly (`src/config.ts` → `BACKEND_FASTAPI_PORT`).

The backend creates `tasks.db` (SQLite) in its working directory on first run via
`Base.metadata.create_all()` — delete it to reset all data.

## Backend API

| Method | Path | Body | Response |
|---|---|---|---|
| GET | `/` | — | `{"message": "Hello World"}` |
| GET | `/tasks/?skip=&limit=` | — | `Task[]` |
| GET | `/task/{task_id}` | — | `Task` (404 if missing) |
| POST | `/tasks/` | `TaskCreate` | `Task` |
| PUT | `/task/{task_id}` | `TaskUpdate` | `200` (404 if missing) |
| DELETE | `/task/{task_id}` | — | `200` (404 if missing) |

`Task` fields: `id: int`, `description: str`, `date: datetime` (ISO-8601), `is_completed: bool`.
`TaskCreate`/`TaskUpdate` carry `description`/`date`/`is_completed` (no partial-update support —
`update_task` always sends the full object). Note the singular `/task/{id}` (not `/tasks/{id}`)
for get/update/delete, and the trailing slash on the plural `/tasks/` for list/create.

## Applications

| Application | Use-case | Backend surface |
|---|---|---|
| load_tasks | On mount, the app fetches and renders all saved tasks | `GET /tasks/?limit=100` |
| create_task | User types a description, clicks ADD, task appears in the active list tagged Today | `POST /tasks/` |
| complete_task | User clicks the check icon; task moves to the Completed section | `PUT /task/{task_id}` (full `TaskUpdate`, `is_completed: true`) |
| delete_task | User clicks the × button on any task; it's permanently removed | `DELETE /task/{task_id}` |
| filter_tasks | User toggles Today/Yesterday/Earlier/Completed tag chips to show/hide buckets | Client-side only — no additional network requests, filters the already-fetched task list |
| view_statistics | User clicks the bar-chart icon; a modal shows a Chart.js doughnut of task counts | Client-side only — chart is built from the already-fetched task list, no dedicated stats endpoint |
